## 1. 产品定义

### 1.1 定位
单机自用的"agent 套餐调度台"(Windows 桌面应用):一个入口,把任务(含附件)派发给本机已安装的多个 agent 客户端(官方 CLI)执行,轮流/按需消耗各客户端账号绑定的付费套餐额度。

### 1.2 价值
多套餐额度池化;失败可降级重跑(可开关);会话可续聊迭代;全程官方进程+登录态,风控风险收敛到"用量节奏"。

### 1.3 明确不做(边界)
- 不做 agent 互跳委派(P2 可选);不调 API、不反代、不逆向(WorkBuddy 不入首版);
- 不搬运客户端自身数据(会话只存 sessionId 引用);不复制用户附件本体(只存路径引用);
- 不存储任何凭据/API key/token;不做多用户/云端/商业分发。

## 4. 总体架构

### 4.1 分层
```
表现层:桌面面板 / 托盘 / 热键 / 选中文本发送 / (可选 MCP 网关)
核心层(core):Orchestrator · Registry · DriverManager · Throttle · Failover
             · Usage · Journal · Launcher · HealthCheck · ArtifactScanner · WorkspaceManager
驱动层(drivers/*):官方 CLI 子进程适配(per 客户端一个包)
存储层:SQLite(状态/事件/审计/工作区登记) + YAML(配置) + assets(logo) + logs(自诊)
```

### 4.2 进程模型
- 单宿主 Electron 主进程内嵌 core;**单实例锁**:`app.requestSingleInstanceLock()` 失败即退出并唤起已有窗口;
- driver 子进程每任务一个,stdio 管道通信;子进程崩溃不影响宿主;宿主重启后从 SQLite 恢复,running→interrupted;
- **优雅退出**:托盘"退出"时若存在 running 任务,弹"等待完成/取消并退出/强制退出(将标记 interrupted)"三选。

### 4.3 控制边界(实际控制的性质,不变)
做的:探测(文件系统+注册表 HKCU 读)、spawn 官方 CLI 传官方参数、读 stdio 解析、终止自身进程树、deep link 唤起、读写自家数据。
绝不做的:不注入/hook、不拦截转发请求、不用非文档参数、不读写客户端私有数据、不碰凭据。
> v5 说明:WorkBuddy"逆向"通道与 4.3 红线冲突,维持⛔不入首版,与边界自洽。

### 4.4 权限清单(不变)
无需管理员;普通文件读写、子进程、HKCU 读、全局热键、通知。

### 4.5 数据目录统一约定
`BASE = %APPDATA%\AgentDrove`,子目录:`data/`(SQLite)、`config/`(YAML)、`assets/logos/`、`logs/`、`workspaces/`(派生工作区)。dev/prod 统一由 `paths.ts` 计算,禁止散写。

## 5. 数据与存储设计

### 5.1 七类存储(继承,增补)
| 类别 | 形式 | 位置 | 原则 |
|---|---|---|---|
| 1 状态库 | SQLite(WAL) | `data\console.db` | 唯一事实源;启动完整性检查,**损坏或迁移失败统一走"备份重命名+重建+提示恢复"一套机制**(见 5.5) |
| 2 配置 | YAML | `config\` | 内置默认+用户覆盖合并;损坏时按内置默认启动,警示文件路径,提供"重置配置" |
| 3 会话引用 | sessionId | DB 字段 | 不复制客户端会话;失效即提示 |
| 4 产物与附件 | **路径引用** | 用户原路径/workspaces | 不复制本体;附件只引用原路径 |
| 5 资源缓存 | 图片 | `assets\logos\` | detector 提取;失败用内置占位 |
| 6 自诊日志 | pino 滚动(10MB×5) | `logs\` | 不含 prompt 正文(仅哈希)与凭据 |
| 7 敏感信息 | 不存储 | — | 凭据永远留在客户端 |

### 5.2 SQLite Schema(v5 增补:dailyTaskCap 落库、kind 全集内联、cwd 默认、user_version=3)

```sql
PRAGMA journal_mode=WAL; PRAGMA user_version=3;

CREATE TABLE agents (
  id TEXT PRIMARY KEY, label TEXT NOT NULL, driver TEXT NOT NULL,
  entry TEXT NOT NULL, version TEXT, logo_path TEXT,
  plan_json TEXT NOT NULL,          -- PlanInfo{name,quotaKind,modelIds,dailyTaskCap,maxConcurrency}
                                    -- dailyTaskCap 必填,默认 20(6.3 入队硬上限;settings.throttle 不再设 cap)
                                    -- maxConcurrency 必填,默认 1(每客户端并发,6.3;收敛骨架 AgentProfile.maxConcurrency 的散置)
  models_json TEXT NOT NULL,        -- 展示用;qoder 可选/可刷新,zcode 跟随客户端(见 R2)
  default_model TEXT NOT NULL,      -- failover 换端时的模型映射目标(6.4);zcode 填哨兵 'client-follow'(见下)
  enabled INTEGER NOT NULL DEFAULT 1,
  supported_versions TEXT           -- driver 兼容版本范围声明,越界仅 warning
);

CREATE TABLE tasks (
  id TEXT PRIMARY KEY, agent_id TEXT NOT NULL REFERENCES agents(id),
  model_id TEXT NOT NULL,           -- 实际执行模型;failover 换端时=目标 default_model;
                                    -- zcode 无模型参数(R2),统一记哨兵 model_id='client-follow',
                                    -- registry.resolveModel 对 modelSwitch='none' 客户端豁免 defaultModel∈models 校验并透传哨兵
  prompt TEXT NOT NULL,
  cwd TEXT NOT NULL,                -- v5 改必填:缺省时入队前落默认目录 %BASE%\workspaces\default(6.6)
  state TEXT NOT NULL,              -- queued|running|completed|failed|canceled|interrupted
  session_id TEXT, parent_id TEXT, error TEXT,
  attachments_json TEXT,            -- [{path,kind}] 引用,不落本体;failover 原样继承
  tool_policy_json TEXT,            -- {denyList[]|maxTurns};failover 原样继承
  created_at INTEGER NOT NULL, started_at INTEGER, finished_at INTEGER,
  retry_of TEXT, attempt INTEGER NOT NULL DEFAULT 1,
  origin TEXT NOT NULL DEFAULT 'panel'   -- panel|hotkey|selection|tray|mcp|failover
                                         -- 入口映射:主面板发布框=panel;全局热键迷你条=hotkey;
                                         -- 选中文本发送=selection;托盘快速派发=tray;MCP=mcp;failover/重试派生=failover
);
CREATE INDEX idx_tasks_agent ON tasks(agent_id, created_at);
CREATE INDEX idx_tasks_state ON tasks(state);

CREATE TABLE events (
  task_id TEXT NOT NULL, seq INTEGER NOT NULL,
  kind TEXT NOT NULL, payload TEXT NOT NULL, at INTEGER NOT NULL,
  PRIMARY KEY (task_id, seq)
);
-- v5:kind 全集与产生方(内联,取代"与 v3 一致"的外部引用)
--   state-changed : Orchestrator 状态迁移
--   message       : driver 转发的 stdout/stderr/agent 输出(批量落库,见 6.8)
--   artifact      : ArtifactScanner(run 终态扫描,见 6.2 规范 5)
--   progress      : driver 从输出流解析的进度行(可选,无进度输出的客户端不发)
--   usage         : driver 从 CLI JSON 输出提取的用量(zcode --json 待 V3;无则不发)
--   warning       : driver 解析容错(6.2 规范 3)与 supportedVersions 越界警告

CREATE TABLE workspaces (
  id TEXT PRIMARY KEY, task_id TEXT NOT NULL,
  path TEXT NOT NULL,
  kind TEXT NOT NULL,               -- worktree|tempcopy|userdir(userdir=用户在发布框指定或缺省默认目录,见 6.6)
  source TEXT, status TEXT NOT NULL,    -- active|done|cleaned
  created_at INTEGER NOT NULL, cleanup_after INTEGER
);

CREATE TABLE usage (
  agent_id TEXT NOT NULL, day TEXT NOT NULL,  -- 本地时区 YYYY-MM-DD
  task_count INTEGER NOT NULL DEFAULT 0,      -- 入队+1;排队取消 -1 记回产生时的原 day 行(6.3)
  estimated INTEGER NOT NULL DEFAULT 0,       -- V3 有结论前恒 0;有则取 CLI 实际 token 数
  PRIMARY KEY (agent_id, day)
);

CREATE TABLE journal (
  id INTEGER PRIMARY KEY AUTOINCREMENT, at INTEGER NOT NULL,
  action TEXT NOT NULL, origin TEXT NOT NULL,
  agent_id TEXT, task_id TEXT, detail TEXT
);
```

### 5.3 配置 schema(增 --mode 与暂停持久化)

```yaml
task:
  defaultTimeoutMs: 600000
  failover: { enabled: false, maxRetries: 1 }
  confirmRetry: true              # 重试前确认(重试会再消耗套餐)
  defaultToolPolicy: { denyList: [], maxTurns: null }
  defaultMode: build              # v5:zcode --mode 档位(build|edit|plan;yolo 仅 Danger 开)
  workspaceCleanupHours: 24
ui: { theme: auto, language: zh-CN, startMinimized: true, autoStart: false }
hotkey: "Ctrl+Shift+Space"
throttle: { globalConcurrency: 2, minIntervalMs: 8000, jitterMs: 4000 }
# throttle 语义:globalConcurrency=全局;minIntervalMs/jitterMs=**每客户端独立节拍**(距该客户端上次放行的间隔,cap 与每客户端并发在 agents.plan_json,见 6.3)
notify: { onComplete: true, onFail: true }
mcp: { enabled: false, port: 18731 }
schedulerPaused: false           # v5:托盘"暂停调度"状态持久化(放行闸,见 6.3)
danger: { allowYolo: false }     # v5:--mode yolo 默认禁止,Danger 区二次确认开启
```

### 5.4 数据生命周期(v5 补全保留期)
- **tasks+events:90 天**滚动清理;journal:**180 天**;usage:永久(体积极小);清理在启动时+每日 03:00 触发,running/interrupted 任务及其事件跳过;
- 派生工作区:`cleanup_after` 到期清理(默认 24h);任务完成用户可在详情区提前"合并产物/打开目录/立即清理";
- 附件引用随任务存留;原文件被用户移动后任务详情显示"附件不可达";
- 导出:设置页"导出数据(JSON)"/"导出本周报告(CSV)";卸载前提示。

### 5.5 迁移与故障恢复(v5 合并为一套)
`user_version` 递增式迁移,事务包裹;**迁移失败与启动完整性检查失败统一处理:备份重命名(`console.db.bak-<ts>`)+重建空库+通知用户**,不再单独设只读安全模式。

## 6. 核心领域设计

### 6.1 任务状态机(v5 补时序与放行语义)

```
queued ─► running ─► completed
   │         │ └──► failed ─(failover:attempt+1, retry_of 链接,见 6.4)
   │         ├──► canceled(用户取消)
   └► canceled   宿主崩溃:running → interrupted(重启标记;可"重试"派生 / "标记为失败"→IPC tasks:mark-failed)
```
- **取消时序(v5 明确)**:running 任务取消 = 先 abort → driver `taskkill /T` 终止进程树(失败重试 1 次)→ 落 `canceled` → **canceled 同样执行产物扫描**(R14);
- **扫描边界(v5.1 补)**:interrupted 经 `tasks:mark-failed` 转 failed 时原 run 已结束,**补做一次产物扫描**(工作区在 cleanup 时限内通常仍在;已清理则跳过并记 warning);**queued 直接取消不扫描**(从未 run,无变更);
- **提交防抖**:同内容任务 5 秒内重复提交仅提示确认,不重复入队;
- **放行语义(v5 改述,消除 FIFO 歧义)**:按入队序**扫描**就绪队列,**跳过**暂不满足放行条件的任务,取第一个满足者放行(防饥饿:同一客户端连续占槽时放行他客户端)。

### 6.2 Driver 接口(v5 增量:按实测修正模型参数语义)

```ts
export interface DetectedAgent { id; label; entry; version?; logoPath?; cliEntry? }

export interface DriverRunOptions {
  agent: AgentProfile; modelId: ModelId;
  input: TaskInput;                // { prompt, cwd, sessionId?, attachments?, toolPolicy? }
  emit: (e: StoredEvent) => void;
  signal: AbortSignal;
  onSpawn?: (pid: number) => void;
}

export interface AgentDriver {
  readonly id: string;
  readonly supportedVersions?: string;      // 如 zcode ">=0.16 <0.17",越界发 warning
  detect(entries: string[]): Promise<DetectedAgent | null>;
  health(agent: AgentProfile): Promise<{ ok: boolean; reason?: string }>;
  resolveModelArg(modelId: ModelId, profile: AgentProfile): string[];
  //  v5 实测语义:zcode 无 --model → zcode 驱动返回 [](模型跟随客户端),qoder 待 V5
  run(options: DriverRunOptions): Promise<number>;
  fetchModels?(profile: AgentProfile): Promise<ModelPreset[]>;
}
```
实现规范(全量):
1. 编码:spawn `encoding:'buffer'` + UTF-8 校验失败回退 GBK(iconv-lite);
2. 进程清理:取消/完成按进程树终止(`taskkill /T` 封装),看门狗默认 `defaultTimeoutMs`,使用**单调时钟**;睡眠唤醒后若超时按超时处理;
3. 解析容错:解析失败原样透传 message + `warning` 事件;
4. **cwd 校验**:run 前检查存在且可写,否则直接 failed(不 spawn);
5. **产物扫描**(v5.1 定基线):run 到达任意终态(completed/failed/canceled)后扫描,产出 `artifact` 事件;逻辑在 core 的 ArtifactScanner,driver 只提供工作区路径。扫描基线分场景——
   - **worktree**:以分支创建点为基线,变更清单 = `git status --porcelain`(未提交)∪ `git diff --name-only <创建点HEAD>`(agent 已 commit 的变更),两者合集;
   - **tempcopy/userdir**:**目录快照 diff,快照建立时机=该任务开始 run 前**(同一工作区多次 run 以最近一次 run 前刷新基线);排除 `.git/`、`node_modules/`、`dist/`、`.cache/`(ArtifactScanner 内置常量,不做配置);
6. env 继承 + per-agent 覆盖;附件参数仅对声明支持的客户端透传(不支持则派发前提示,不静默丢弃);
7. **v5 安全强制**:zcode 派发恒显式传 `--mode <task.defaultMode>`(实测无头默认 yolo,绝不依赖默认值)。

### 6.3 节流器(v5 补 cap 语义与暂停闸)

- 参数:全局并发 2(settings.throttle.globalConcurrency)/ **每客户端并发 1(`agents.plan_json.maxConcurrency`,默认 1,收敛骨架 AgentProfile.maxConcurrency 散置)** / 最小间隔+抖动(**per-client 节拍**:距该客户端上次放行≥minIntervalMs,叠加 jitterMs);**dailyTaskCap 硬上限存 `agents.plan_json.dailyTaskCap`(默认 20)**;
- **计数语义**:**cap 在入队时检查**——当日 `task_count ≥ cap` 直接拒绝入队并提示,不产生任务记录;入队即 +1;**排队中取消返还 -1,且记回计数产生时的原 day 行**(跨零点不写新日,新日不会出现负数);已 running 后取消不返还;失败/重试每次尝试独立计(task_count 按 attempt 累加);日界按本地时区零点,运行时缓存跨零点自动失效;
- **公平调度**:见 6.1 放行语义;
- **暂停调度(v5 明确)**:= **放行闸**——暂停时 drain 不放行新任务,不影响已 running;状态写 `settings.schedulerPaused` 持久化,重启恢复;恢复放行时按当日重查 cap 与间隔,排队任务按 6.1 扫描放行。

### 6.4 Failover(v5 补模型映射与附件继承)

- 触发 failed 且 `failover.enabled`;
- **候选筛选**(按序跳过):disabled / 当日已满额 / health 不 ok(**强制绕过 6.7 TTL 缓存**)/ 占用任务同 cwd / 未安装 / **不支持任务附件**;全不可用 → 保持 failed,error 附"无可用降级目标";
- **模型映射(v5 新增)**:派生新任务时 `model_id` 改为**目标客户端 `default_model`**(各端命名空间不互通,原 modelId 不可寻址);目标为 zcode 时取其哨兵 `client-follow`(见 5.2);新任务如实记录实际 model_id;
- **附件与策略继承(v5 新增)**:`attachments_json`/`tool_policy_json` 原样继承;目标不支持附件的候选已在筛选中跳过;
- 工作区语义:默认同工作区继续(failover 同工作区继续时不新建 worktree);可选"新工作区重来";
- **手动重试(v5 明确)**:与 failover 同构——派生新任务、attempt+1、retry_of 记链,区别仅 origin='panel' 且不换客户端;重试与 failover 都走节流器,无豁免。

### 6.5 会话续聊(v5 按实测修正)

- 追加提示词 → 新任务 `parent_id` 链 + session_id 透传;zcode 实测支持 **`--resume <sessionId>`(按 id 续接,强于 v4 假设的 `-c` 最近会话语义)**,优先用 `--resume`;
- **session_id 提取方式(v5 明确待验证)**:从 zcode `-p` 输出(stdout 或 `--json`)提取,提取步骤与判定标准见 **V2**;V2 有结论前,续聊降级 `-c`(当前 cwd 最新会话)语义并在 UI 标注;
- **running 父任务拒绝续聊(v5 新增)**:state=running 时"继续对话"直接拒绝,提示等待完成或先取消,不允许并发续聊;
- **失效处理**:CLI 返回会话不存在/清理时 task failed,error="会话已不可用",操作区提供"转为新会话重试";
- 父任务被本地清理(90 天,5.4)不影响已记录的 session_id,但 CLI 侧可能已失效,按上条处理。

### 6.6 工作区策略(v5 补降级与 userdir)

- **同 cwd 互斥(v5.1 明确判据)**:互斥按**任务状态**判定——编排层放行(6.1 扫描)前检查该 cwd 是否已有 running 任务占用,有则跳过该任务放行后续;queued 任务不占用 cwd(放行时才判),两个同 cwd 的 queued 任务天然串行执行。**缺省目录 `%BASE%\workspaces\default` 的任务因此串行,是有意行为**(缺省=无文件隔离诉求,串行最安全);workspaces 行仅作登记与清理,不作为互斥判据;
- **kind=userdir 定义(v5 新增)**:用户在发布框直接指定的工作目录,以及 cwd 缺省时落入的默认目录 `%BASE%\workspaces\default`(首次使用时创建),均登记 `workspaces` 表;**行 status 迁移时机:占用任务(该行 path 对应 cwd 的 running 任务)到达终态时 active→done,到期清理或立即清理后 done→cleaned**;userdir 的"立即清理"仅解除登记、不删目录;
- 工作区全部登记 `workspaces` 表(生命周期见 5.4);
- 产物默认留在工作区,详情区提供产物操作(见 7.2 与 `workspaces:merge`);**不做静默写回源目录**。

### 6.7 健康检查与登录引导(v5 补缓存绕过)

- 派发前 `health()`(在放行时执行,非入队时);结果缓存 TTL 60s;**手动"重查"与 failover 候选筛选强制绕过缓存**(避免命中旧缓存造成降级死循环);未登录 → 引导卡(唤起 GUI 登录 → 完成后点"继续"复检,复检同样绕过缓存);
- **health 不 ok 时任务去向(v5.1 明确)**:任务落 `failed`,error 附"客户端不健康:<reason>";**入队已 +1 的计数按原 day 行返还 -1(不占额)**;若 `failover.enabled` 则按 6.4 走降级。
- 自检命令实测:`zcode doctor` exit=0 ✅;qoder/trae 见 V6。

### 6.8 事件管道与渲染背压

- core 内 message 事件**批量落库**(内存队列,500ms 窗口或 200 条 flush);
- 推送渲染层按窗口合并,通道名统一为 **`tasks:events-batch`**(v4 中 `tasks:event-batch` 为笔误,以此为准);
- 渲染层时间线用虚拟列表;老事件分页拉取走 `tasks:events-page`(按 seq 倒序翻页,见 7.5)。

| Trae | `trae://` → `"E:\Trae_guoji\Trae.exe" --open-url -- "%1"`;`trae-cn://` → `"E:\Trae\Trae CN.exe" --open-url -- "%1"` ✅ | 同上;国际版/CN 版按 agents 登记入口区分 |
