## 1. 产品定义

### 1.1 定位
单机自用的"agent 套餐调度台"(Windows 桌面应用):一个入口,把任务(含附件)派发给本机已安装的多个 agent 客户端(官方 CLI)执行,轮流/按需消耗各客户端账号绑定的付费套餐额度。

### 1.2 价值
多套餐额度池化;失败可降级重跑(可开关);会话可续聊迭代;全程官方进程+登录态,风控风险收敛到"用量节奏"。

### 1.3 明确不做(边界)
- 不做 agent 互跳委派(P2 可选);不调 API、不反代、不逆向(WorkBuddy 不入首版);
- 不搬运客户端自身数据(会话只存 sessionId 引用);不复制用户附件本体(只存路径引用);
- 不存储任何凭据/API key/token;不做多用户/云端/商业分发。

## 4. 总体架构

### 4.1 分层
```
表现层:桌面面板 / 托盘 / 热键 / 选中文本发送 / (可选 MCP 网关)
核心层(core):Orchestrator · Registry · DriverManager · Throttle · Failover
             · Usage · Journal · Launcher · HealthCheck · ArtifactScanner · WorkspaceManager
驱动层(drivers/*):官方 CLI 子进程适配(per 客户端一个包)
存储层:SQLite(状态/事件/审计/工作区登记) + YAML(配置) + assets(logo) + logs(自诊)
```

### 4.2 进程模型
- 单宿主 Electron 主进程内嵌 core;**单实例锁**:`app.requestSingleInstanceLock()` 失败即退出并唤起已有窗口;
- driver 子进程每任务一个,stdio 管道通信;子进程崩溃不影响宿主;宿主重启后从 SQLite 恢复,running→interrupted;
- **优雅退出**:托盘"退出"时若存在 running 任务,弹"等待完成/取消并退出/强制退出(将标记 interrupted)"三选。

### 4.3 控制边界(实际控制的性质,不变)
做的:探测(文件系统+注册表 HKCU 读)、spawn 官方 CLI 传官方参数、读 stdio 解析、终止自身进程树、deep link 唤起、读写自家数据。
绝不做的:不注入/hook、不拦截转发请求、不用非文档参数、不读写客户端私有数据、不碰凭据。

### 4.4 权限清单(不变)
无需管理员;普通文件读写、子进程、HKCU 读、全局热键、通知。

### 4.5 数据目录统一约定
`BASE = %APPDATA%\Agent操作台`,子目录:`data/`(SQLite)、`config/`(YAML)、`assets/logos/`、`logs/`、`workspaces/`(派生工作区)。dev/prod 统一由 `paths.ts` 计算,禁止散写。

## 5. 数据与存储设计

### 5.1 七类存储(继承 v3,增补)
| 类别 | 形式 | 位置 | 原则 |
|---|---|---|---|
| 1 状态库 | SQLite(WAL) | `data\console.db` | 唯一事实源;启动完整性检查,损坏时备份重命名+重建+提示恢复 |
| 2 配置 | YAML | `config\` | 内置默认+用户覆盖合并;损坏时按内置默认启动,警示文件路径,提供"重置配置" |
| 3 会话引用 | sessionId | DB 字段 | 不复制客户端会话;失效即提示 |
| 4 产物与附件 | **路径引用** | 用户原路径/workspaces | 不复制本体;附件只引用原路径 |
| 5 资源缓存 | 图片 | `assets\logos\` | detector 提取;失败用内置占位 |
| 6 自诊日志 | pino 滚动(10MB×5) | `logs\` | 不含 prompt 正文(仅哈希)与凭据 |
| 7 敏感信息 | 不存储 | — | 凭据永远留在客户端 |

### 5.2 SQLite Schema(v4 增 workspaces、附件与来源字段)

```sql
PRAGMA journal_mode=WAL; PRAGMA user_version=2;

CREATE TABLE agents (
  id TEXT PRIMARY KEY, label TEXT NOT NULL, driver TEXT NOT NULL,
  entry TEXT NOT NULL, version TEXT, logo_path TEXT,
  plan_json TEXT NOT NULL, models_json TEXT NOT NULL,
  default_model TEXT NOT NULL, enabled INTEGER NOT NULL DEFAULT 1,
  supported_versions TEXT                      -- driver 兼容版本范围声明
);

CREATE TABLE tasks (
  id TEXT PRIMARY KEY, agent_id TEXT NOT NULL REFERENCES agents(id),
  model_id TEXT NOT NULL, prompt TEXT NOT NULL,
  cwd TEXT, state TEXT NOT NULL,               -- queued|running|completed|failed|canceled|interrupted
  session_id TEXT, parent_id TEXT, error TEXT,
  attachments_json TEXT,                       -- [{path,kind}] 引用,不落本体
  tool_policy_json TEXT,                       -- {allowOnly?|denyList|maxTurns}
  created_at INTEGER NOT NULL, started_at INTEGER, finished_at INTEGER,
  retry_of TEXT, attempt INTEGER NOT NULL DEFAULT 1,
  origin TEXT NOT NULL DEFAULT 'panel'         -- panel|hotkey|selection|mcp|failover
);
CREATE INDEX idx_tasks_agent ON tasks(agent_id, created_at);
CREATE INDEX idx_tasks_state ON tasks(state);

CREATE TABLE events (
  task_id TEXT NOT NULL, seq INTEGER NOT NULL,
  kind TEXT NOT NULL,                          -- state-changed|message|artifact|progress|usage
  channel TEXT, payload TEXT NOT NULL, at INTEGER NOT NULL,
  PRIMARY KEY (task_id, seq)
);

CREATE TABLE workspaces (                       -- v4 新增:派生工作区登记
  id TEXT PRIMARY KEY, task_id TEXT NOT NULL,
  path TEXT NOT NULL, kind TEXT NOT NULL,       -- worktree|tempcopy|userdir
  source TEXT, status TEXT NOT NULL,            -- active|done|cleaned
  created_at INTEGER NOT NULL, cleanup_after INTEGER
);

CREATE TABLE usage (
  agent_id TEXT NOT NULL, day TEXT NOT NULL,    -- 本地时区 YYYY-MM-DD,零点重置
  task_count INTEGER NOT NULL DEFAULT 0,        -- 计入语义:入队+1,排队取消-1(见 6.3)
  estimated INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (agent_id, day)
);

CREATE TABLE journal (
  id INTEGER PRIMARY KEY AUTOINCREMENT, at INTEGER NOT NULL,
  action TEXT NOT NULL, origin TEXT NOT NULL,   -- v4 新增来源
  agent_id TEXT, task_id TEXT, detail TEXT
);
```

### 5.3 配置 schema(继承 v3,增 toolPolicy 与重试确认)

```yaml
# settings.yaml(节选新增项)
task:
  defaultTimeoutMs: 600000
  failover: { enabled: false, maxRetries: 1 }
  confirmRetry: true              # 重试前确认(重试会再消耗套餐)

danger: { allowYolo: false }      # v4:--yolo 类参数默认禁止,Danger 区二次确认开启
```

### 5.4 数据生命周期(增补)
- 派生工作区:`cleanup_after` 到期清理(默认 24h),任务完成用户可在详情区提前"合并产物/打开目录/立即清理";
- 附件引用随任务存留;原文件被用户移动后任务详情显示"附件不可达";
- 导出:设置页"导出数据(JSON)"/"导出本周报告(CSV)";卸载前提示。

### 5.5 迁移
`user_version` 递增式;任何迁移失败回滚事务,进入只读安全模式。

## 6. 核心领域设计

### 6.1 任务状态机(v4 增 interrupted 操作与幂等)

```
queued ─► running ─► completed
   │         │ └──► failed ─(failover:attempt+1, retry_of 链接,见 6.4)
   │         ├──► canceled(用户取消)
   └─► canceled    宿主崩溃:running → interrupted(重启标记;可"重试"派生 / "标记为失败")
```
- **提交防抖**:同内容任务 5 秒内重复提交仅提示确认,不重复入队;
- 事件 kind 全集与 v3 一致;`message` 批量落库(见 6.8)。

### 6.2 Driver 接口(v4 增量:版本声明、自检缓存、cwd、产物扫描)

```ts
export interface DetectedAgent { id; label; entry; version?; logoPath?; cliEntry? }

export interface DriverRunOptions {
  agent: AgentProfile; modelId: ModelId;
  input: TaskInput;                // v4:{ prompt, cwd?, sessionId?, attachments?, toolPolicy? }
  emit: (e: StoredEvent) => void;
  signal: AbortSignal;
  onSpawn?: (pid: number) => void;
}

export interface AgentDriver {
  readonly id: string;
  readonly supportedVersions?: string;      // v4 兼容范围声明(如 ">=3.10 <4"),越界仅警告
  detect(entries: string[]): Promise<DetectedAgent | null>;
  health(agent: AgentProfile): Promise<{ ok: boolean; reason?: string }>;
  resolveModelArg(modelId: ModelId, profile: AgentProfile): string[];
  run(options: DriverRunOptions): Promise<number>;
  fetchModels?(profile: AgentProfile): Promise<ModelPreset[]>;
}
```
实现规范(全量):
1. 编码:spawn `encoding:'buffer'` + UTF-8 校验失败回退 GBK(iconv-lite);
2. 进程清理:取消/完成按进程树终止(`taskkill /T` 封装),看门狗默认 `defaultTimeoutMs`,使用**单调时钟**(不受系统挂起影响);睡眠唤醒后若超时按超时处理;
3. 解析容错:解析失败原样透传 message + warning;
4. **cwd 校验**:run 前检查存在且可写,否则直接 failed(不 spawn);
5. **产物扫描**:run 结束后(成功或失败都扫),对工作区执行 git status --porcelain(或目录快照 diff),产出 `artifact` 事件列表;此逻辑放 core 的 ArtifactScanner,driver 只提供工作区路径;
6. env 继承 + per-agent 覆盖;附件参数仅对声明支持的客户端透传(不支持则派发前提示,不静默丢弃)。

### 6.3 节流器(补计数语义与公平性)

- 参数:v3 同;`dailyTaskCap` 硬上限;
- **计数语义**:入队即 +1;**排队中取消返还 -1**;已 running 后取消不返还;失败/重试每次尝试独立计(task_count 按 attempt 累加);日界按本地时区零点,运行时缓存跨零点自动失效;
- **公平调度**:全局就绪队列 FIFO;放行条件=全局空闲位 AND 该客户端空闲位 AND 距该客户端上次放行≥minInterval;不满足则顺延后续任务(避免饥饿:同一客户端连续占槽时,第二个任务暂缓并放行他客户端)。

### 6.4 Failover(补寻址算法)

- 触发 failed 且 `failover.enabled`;
- **候选筛选**(按序跳过):disabled / 当日已满额 / health 不 ok / 占用任务同 cwd 的客户端 / 不可用(未安装);全不可用 → 任务保持 failed,error 附"无可用降级目标";
- 工作区语义:**默认同工作区继续**(共享文件状态,失败现场可被下一个续接);可选"新工作区重来";
- 重试与 failover 走节流器,无豁免;attempt 与 retry_of 记链。

### 6.5 会话续聊(补失效处理)

- 追加提示词 → 新任务 `parent_id` 链 + session_id 透传;zcode 若仅支持最近会话续接(`-c` 语义)则标注;
- **失效处理**:CLI 返回会话不存在/清理时,task failed,error="会话已不可用",操作区提供"转为新会话重试";
- 父任务被本地清理(90 天策略)不影响已记录的 session_id,但 CLI 侧可能已失效,按上条处理。

### 6.6 工作区策略(v4 补登记与清理)

- 同 cwd 全局互斥(编排层强制);多客户端并行默认分工作区:git 仓库用 worktree(分支 `ac/<taskId>`),非 git 复制到 `workspaces\<taskId>`;
- 工作区全部登记 `workspaces` 表(生命周期见 5.4);
- failover 同工作区继续时不新建 worktree;
- 产物默认留在工作区,详情区"打开目录/合并产物/立即清理";**不做静默写回源目录**。

### 6.7 健康检查与登录引导(补缓存)

- 派发前 `health()`;结果缓存 TTL 60s,失败可手动重查;未登录 → 引导卡(唤起 GUI 登录 → 完成后点"继续"复检);health 失败不占额。

### 6.8 事件管道与渲染背压(v4 新增)

- core 内 message 事件**批量落库**(内存队列,500ms 窗口或 200 条 flush);
- 推送渲染层同样按窗口合并(每窗口一条 `tasks:event-batch`);
- 渲染层时间线用虚拟列表,10 万级事件流畅;老事件分页加载。

### 6.9 唤起模块(补实现方式)

| 客户端 | 唤起 GUI | 实现 |
|---|---|---|
| ZCode / Qoder / Trae | 各自 exe / 协议 | 优先 `shell.openExternal(deepLink)`,失败回退 `child_process.spawn(entry,{detached:true})`;会话跳转 deep link 格式待验证,降级"唤起后人工定位" |

## 7. 桌面应用设计(v4 增补)

### 7.1 窗口/托盘/单实例
主窗 1200×760(最小 980×640);关闭=最小化托盘(可改);开机自启默认关;**单实例锁**(R16);托盘菜单:打开面板/快速派发/打开 X 客户端(动态)/暂停调度/退出(存在运行任务时三选确认,见 4.2)。

### 7.2 三栏布局
- 左栏客户端梯队:logo+名称+版本+套餐形态+今日任务数/上限+软额度条+启停+健康灯;
- 中栏任务流:发布框(附件、模型、工作区、批量粘贴、派发方式)+任务卡流(**搜索(关键词/客户端/状态/日期)、排序、批量选择(取消/删除)**);
- 右栏详情:元信息+时间线(虚拟列表)+操作区(继续对话/重试(可配确认)/换客户端/取消/打开客户端/打开工作区/奖品操作)。

### 7.3 任务卡规范

### 7.4 通知/热键/快捷键
